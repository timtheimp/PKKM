# PKKM — Standalone Kingdom Manager

## Source analysis
Source workbook: `C:\Users\darks\Downloads\Kingdom of Template.xlsx`.

The workbook has 10 sheets: Kingdom, Capital, Capital Map, Turn, City #, City # Map, Example Map, Multi-District Map, Calendar, and Data. It contains substantial formula-driven kingdom statistics, law/edict and leadership modifiers, settlement/building tracking, city map layouts, a turn tracker, a 12-month calendar, and a building/improvement reference table. The workbook also uses merged cells, a named range (`IMP`), cross-sheet `INDIRECT` references, and Google Sheets compatibility formulas (`__xludf.DUMMYFUNCTION` / `TO_TEXT`). Those Excel formula constructs should not be copied mechanically; implement and test their intended behavior in native C++ domain logic.

## Objective
Build PKKM as a standalone Windows desktop application in C++, developed and built through Visual Studio Code. It should preserve the workbook's kingdom-management utility while replacing fragile spreadsheet formulas with explicit, testable application logic.

## Proposed architecture
- C++17 or newer; CMake project opened in Visual Studio Code.
- Native Windows desktop UI. Qt was unavailable in the supplied environment, so the current shell uses the Windows SDK/Win32 API; keep calculation/domain code framework-independent.
- Local-first persistence using versioned JSON (or SQLite if relational editing/history warrants it); no network dependency.
- Modules: domain models, rules/calculations, persistence/import-export, UI, automated tests.

## Functional scope (initial release)
1. **Kingdom dashboard:** identity/alignment/size, Economy/Loyalty/Stability, control DC, population, unrest, consumption, treasury, vacancies, leadership, laws/edicts, modifiers and improvements.
2. **Settlements:** multiple cities/towns, each with editable population/district overrides, stats, defense, and catalog-backed building inventory. Lot totals, minimum districts, and minimum population are catalog-derived; Economy/Loyalty/Stability catalog bonuses are opt-in per settlement and off by default.
3. **Building catalog and construction:** the reference-data importer, CLI search, settlement inventory selector, lot-derived settlement sizing, opt-in Economy/Loyalty/Stability aggregation, and the atomic domain construction transaction are delivered. Catalog-driven construction costs, discounts, upgrades, placement checks, failed-attempt records, GM terrain facts, persistence, explicit reversal, and native Win32 staging/preview/finalization/history controls are implemented.
4. **Maps:** editable city district/lot grids; visual terrain/corridor labels and building placement; optional presets for the `Capital Map`, `City # Map`, `Example Map`, and `Multi-District Map` sheets. Preserve explicit merged-cell footprints. The map sheets do not define terrain mechanics. The example map's “2x lots” and “4x lots” captions must not be generalized into footprints; use only their specific merged ranges.
5. **Turns and calendar:** monthly turn log, events, holidays, kingdom upgrades and notes; advance turn without losing history.
6. **Persistence:** create/open/save kingdom files; autosave or clear unsaved-change indication; backup-safe writes.
7. **Spreadsheet migration:** read-only import from the supplied workbook or a populated copy, preserving values and mapping supported sheets. Report unsupported formulas/fields rather than silently dropping them. Export CSV/JSON and multi-sheet XLSX reports from schema-v10 JSON.

## Calculation and data rules
- Translate formulas into named functions and document each rule with its workbook cell/formula provenance.
- Separate user-entered values, derived values, and overrides. Never overwrite manual input with a computed value.
- Handle blank/text/numeric states explicitly; this workbook uses text sentinels and formulas that rely on type checks.
- Confirm edge cases against workbook behavior: kingdom size/population thresholds, vacancy penalties, edict/law modifiers, building counts/lots, upgrades, and settlement aggregation.
- Do not claim formula parity for spreadsheet compatibility functions until their output is demonstrated by test cases.

## Open decisions for implementation

The historical source-analysis questions below are resolved for the current release:

- **UI framework:** retain the native Win32 implementation; no Qt migration is planned.
- **Migration priority:** populated-workbook import is implemented within the documented direct-input scope, with unsupported formulas and manual workflows reported rather than guessed.
- **Rules authority:** the supplied Kingmaker PDF is the overall default where sources conflict; the supplemental terrain reference is the default authority specifically for Greenbelt prerequisites where it differs from the workbook; Workbook and City Info remain explicit persisted overrides.

The remaining decisions are feature-specific and should be made before widening automation:

- **City-layout automation boundary resolved:** keep building placement explicit and manual. The PDF graphics and visual D1-D9 grouping may guide display and reference helpers, but PKKM must not infer footprints, enforce adjacency, calculate building legality, or apply automatic city-stat effects.
- **Magic-item generation boundary resolved:** commissioned magic items are player-requested manual records. PKKM may record the named item, recipient, caller-supplied BP cost, turn, and exotic-crafter capacity, but it does not generate item identity, fill settlement slots, create player inventory, or distribute the item automatically. The Pathfinder Core Rulebook creation procedure is reference authority for future optional creation-detail fields; it does not replace Kingmaker settlement slot generation. The settlement random-item slice provides a seeded, non-mutating preview and an explicit `random-items-apply` Upkeep mutation: it creates one auditable category candidate per currently previewed minor/medium/major slot using the captured d20PFSRD all-source profile, applies an equal 50/50 lesser/greater variant chance, loads the normalized 1,014-record catalog beside the runtime and in both release package surfaces, populates empty or sold slots, resolves unambiguous source tables into generated stock, and persists named `manual_resolution` states for spell-selection or multi-subtable branches. Purchase/removal transitions are implemented as explicit stock removal, `random-items-availability` provides the seeded non-mutating 75% base-value check, and the native settlement manager displays persisted random magic-item stock with confirmed removal for generated records; manual-resolution records remain visible and protected pending source-defined resolution.
- **Event-consequence boundary resolved:** non-numeric event consequences remain manual with explicit GM confirmation. PKKM may record consequence notes, caller-entered numeric Treasury/Unrest deltas, Kingdom Size intent, hex-loss intent, and Anarchy completion flags, but it must not select a lost hex, change Kingdom Size, or resolve Anarchy automatically.
- **Terrain route/effect boundary resolved:** route costs, corridor effects, and any resulting kingdom-stat changes remain manual and caller-supplied.
